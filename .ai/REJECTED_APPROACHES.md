# Rejected Approaches

| Approach | Why rejected | Evidence/experience | Reconsider only if |
|---|---|---|---|
| Rigid fixed-hour timetable as primary model | Energy and real work require adaptation | User reported severe afternoon study difficulty | The user explicitly requests calendar enforcement |
| Full planner inside FORGE | Duplicates ChatGPT orchestration and increases input burden | Earlier Tomorrow/dropdown workflow was unclear | Offline planning becomes a hard requirement |
| Tracking JOLT/VERIDRA runtime inside FORGE | They are independent services; automation time is not human focus | Explicit user correction | Cross-app observability becomes a separate product goal |
| Passive activity surveillance | Privacy and noise outweigh benefit | Product decision | Explicit opt-in with a bounded privacy design |
| Dense forms on every mission card | Caused clutter, accidental expansion and unclear controls | 0.6–0.9 GUI iterations and screenshots | Never; use contextual dialogs/Advanced |
| Symbol-only status controls | Meaning was unclear and layout was crowded | 0.9.0 screenshot | Only with persistent text labels |
| Unreviewed AI plan application | Risks stale/duplicate/unsupported changes | Import bug reports | Never |
| Treating code presence as operability | Repeated premature readiness claims | Missing browser/Windows evidence | Never |
